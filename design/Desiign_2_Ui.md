# 数据工坊（Data Workshop）— UI 设计说明

> 依据 `Desiign_1_Requirement.md` 整理；**与当前实现同步**（`frontend/src/`）；界面文案与标签**以中文为主**（侧栏首项 `HOME` 为历史标签，可后续改为中文）；技术栈：Vue 3、Ant Design Vue 4、Vite、TypeScript、部分页使用 ECharts。

---

## 1. 设计目标与原则

| 目标 | 说明 |
|------|------|
| 减少认知负担 | 主流程按「数据 → 数据集 → 训练 → 试跑/评测」顺排，次要能力（合并、导出、系统信息）副栏或顶栏可达。 |
| 与约束一致 | 全路径强调 **CPU 跑训练/推理**；若展示 GPU 探测信息，需附**不参与本工具主路径**的说明（见 §8）。 |
| 可观测性 | 训练与评测页突出日志、曲线、资源占用；长任务有队列与状态机反馈。 |
| 轻量不简陋 | 空状态、加载、失败、取消均有明确文案与可恢复操作。 |

**视觉基线**（与 Ant Design Vue 一致即可）：主色建议偏工具型蓝/靛，侧栏深灰；圆角、间距遵循 AD 默认 token，不额外做重型皮肤。

│ 主导航    │  主内容区（卡片包裹 router-view：表格/表单/图表）     │

- **顶栏「资源信息」**：打开 **`ResourceInfoFloating`**（悬浮层），展示 **CPU / 内存** 等短时刷新数据（调用 `GET /api/system/resources`），与训练页资源区同类信息。  
- **系统信息**：独立路由 **`/system-info`**（`SystemInfo.vue`），展示 Python/Torch/路径等（`GET /api/system/info`、`/api/system/paths`）。  
- **底栏**：当前实现未固定底栏；可选后续增加工作区路径提示。

### 2.1 导航与「导出」

- **无独立「导出」路由**。
- 导出能力体现在：**合并**页面的下载入口；**训练产物**相关入口；**评测报告**页面的导出入口。
- 合并相关示例 API：**`export-zip`**。
- 首页流程图中的「导出」若保留：应对齐真实路由，或改为文案引导。
- **模型管理**：侧栏独立路由 **`/models`**。
- 需求对齐：基础模型来自 **ModelScope** 或 **本机缓存**。
- 训练表单要求：基座模型已在 Hub 列表中存在。

## 3. 页面与组件规格

### 3.0 设置（首页）与模型管理、批次查看

| 路由 | 说明 |
|------|------|
| `/` | **Home**：欢迎与推荐流程卡片；`document.title` 为「设置 · 数据工坊」（`meta.title`）。 |
| `/models` | **模型管理**：魔搭 Hub 模型列表与下载任务；与训练页基座模型下拉联动。 |
| `/batchDataView` | **批次数据查看**：已导入批次的任务列表/预览（与 `GET /api/imports`、`/api/import-tasks` 等配合）。 |

### 3.1 数据导入

**目的**：从 Label Studio 经 API 拉取项目；展示导入后的元数据与可解析图片路径。连接基址与 Token 可 **`PUT /api/label-studio/connection`** 持久化到 SQLite（`app_kv`），界面回显用 **`GET .../connection`**。

| 区域 | 组件/行为 |
|------|-----------|
| 连接配置 | 见下文「连接配置」。 |
| 项目选择 | 见下文「项目选择」。 |
| 结果预览 | 见下文「结果预览」。 |
| 说明区 | 折叠面板：SFT 字段示例与需求 §1.2 一致。 |

**连接配置**
- 表单字段：LS **基址**；**Token**。
- **测试连接** → `POST /api/label-studio/test-connection`。
- **状态**可参考 `GET /api/label-studio/status`（探测配置默认 URL）。

**项目选择**
- 项目列表：`GET /api/label-studio/projects?token=...`。
- **拉取并导入** → `POST /api/label-studio/import`。

**结果预览**
- 批次与任务：`GET /api/imports`、`GET /api/imports/{batch_id}/tasks`。
- 单任务原数据/图片：见同前缀路由。

**空状态**：未连接 LS 时引导用户查看根目录 README 的 Docker 起 LS 方式。

### 3.2 数据集（构建与划分）

**目的**：将导入数据按模板转为 SFT；**qwen-vl** 对话模板、自动补 `<image>`；按比例划分训练/验证/测试；**版本**快照在 `{workspace}/versions/`。

| 子区块 | 内容 |
|--------|------|
| 源数据 | 见下文「源数据」。 |
| 构建选项 | 见下文「构建选项」。 |
| 划分 | 见下文「划分」。 |
| 版本 | 见下文「版本」。 |
| 输出预览 | 见下文「输出预览」。 |

**源数据**
- 选择已导入的 LS **项目**/**任务范围**。
- **只读**显示样本条数。

**构建选项**
- 模板与模型族：**固定提示**「与训练默认 Qwen3-VL 族一致 / qwen-vl 模板」。
- 单选/开关：**是否自动补 `<image>`**。

**划分**
- 三档比例：输入或滑块（**训练**/**验证**/**测试**，三者之和 **100%**）。
- **随机种子**：可选数字输入。

**版本**
- 表格列：**时间**；**备注**；**路径标识**。
- 操作：**回滚**；**导出**。
- **新建处理**前：**强制备注** 或可跳过（产品可选）。

**输出预览**
- 小窗口 JSON 片段预览 **1 条**。
- 用于确认字段形态与 `Readme_1` 中示例一致。

**交互**
- 长耗时操作：**Modal 进度** + **可取消**。
- 完成后：**Toast**。
- 后续动作：**跳「训练」**，或留在本页点 **「去训练」**。
- 全景关系树可选展示：**`GET /api/overview/pipeline`**。
- 关系链：**项目** → **批次** → **数据集版本** → **训练** → **合并**。

### 3.3 训练

**目的**：SFT/LoRA 参数表单、YAML 导入导出、任务队列、日志、曲线、资源监控。

| 子区块 | 内容 |
|--------|------|
| 基础模型 | 见下文「基础模型」。 |
| 超参数 | 见下文「超参数」。 |
| YAML | 见下文「YAML」。 |
| 提交流程 | 见下文「提交流程」。 |
| 任务监控 | 见下文「任务监控」。 |
| 日志 | 见下文「日志」。 |
| 曲线 | 见下文「曲线」。 |
| 资源 | 见下文「资源」。 |

**基础模型**
- 须为 **模型管理** 中已下载的 **ModelScope `model_id`**（后端 **`GET /api/training/jobs`** 创建前会校验 Hub 列表）。
- 表格展示：**参数量** / **内存提示**（例如 2B 约 10GB LoRA，与需求表一致）。

**超参数**
- 控件：**表单** + **部分滑块**。
- 字段示例：LoRA **rank**、**alpha**、**target modules**、**学习率**、**batch**、**梯度累积**、**epochs**、**分辨率** 等（与 `TrainJobCreate` 一致）。

**YAML**
- **`POST /api/training/config/yaml/parse`**
- **`GET /api/training/config/yaml/export`**（可带 `job_id`）

**提交流程**
- **直接训练**：`POST /api/training/jobs`。
- **仅保存参数**：`POST /api/training/jobs/params-only` → 状态 **`parameters_saved`** → **`POST /api/training/jobs/{id}/start`** 再启子进程。
- **表单回写库**：`POST /api/training/form-params?job_id=`

**任务监控**
- 状态含：**`pending`**；**`running`**；**`succeeded`**；**`failed`**；**`cancelled`**；**`parameters_saved`**。
- **取消**：`POST .../cancel`。
- **删除**：`DELETE ...`。
- **继续训练**：`POST .../retry`（同 `output_dir` 续训）。
- **改名**：`PATCH ...`。

**日志（训练页）**
- 轮询：`GET .../logs`。
- 详细行为：见本节「训练日志区」。

**曲线**
- **`GET .../metrics`**：返回 **`series`**（loss / lr 等）与 **`progress`**。
- **ECharts** 与当前选中任务联动。

**资源（训练页）**
- **顶栏「资源信息」** 或 **页内卡片**：调用 **`GET /api/system/resources`**。
- **附**：CPU 执行说明文案。

#### 训练日志区（滚动与跟随）

| 要求 | 说明 |
|------|------|
| 可见滚动 | 日志展示在 **固定高度、纵向滚动** 的等宽区域（`pre` / 虚拟列表均可），训练进行中内容持续增长时，用户能 **上下滚动** 查看任意历史片段。 |
| 默认跟随最新 | 当用户停留在 **底部附近**（实现可定阈值，例如距底部不足约 80px）时，每次日志更新后 **自动滚到底部**，形成「尾部不断追加」的观感。 |
| 暂停跟随 | 用户 **向上滚动** 离开底部区域后，**不再强制滚底**，避免打断阅读；显示 **「跟随最新」** 或 **「回到底部」** 按钮，一键恢复滚底并继续跟随。 |
| 刷新节奏 | **轮询** `GET .../logs`（如 1～2s）。 |
| 高亮与复制 | **ERROR / WARNING** 行关键词高亮（颜色区分即可）；提供 **复制全部日志**。极长日志时可先 **纯文本滚动** 保证流畅，高亮可用虚拟列表或分段渲染逐步增强。 |
| 任务结束 | 任务 **成功/失败/取消** 后停止轮询；保留最终日志，仍可按上述规则滚动查看。 |

**顶栏提醒**：`Alert` 类型 info：训练与推理均在 **纯 CPU** 上执行，速度受本机 CPU/内存影响。

### 3.4 推理沙盒（界面标题：LoRA 验证）

**路由**：`/verify`（`Verify.vue`）。**目的**：对话式 UI；加载本机训练产出或合并模型；**切换模型**可通过 `model_id` / `preload` 减少等待（`POST /api/inference/load`、`unload`）。

| 区域 | 行为 |
|------|------|
| 模型条 | 见下文「模型条」。 |
| 图像上下文 | 见下文「图像上下文」。 |
| 对话区 | 见下文「对话区」。 |
| 会话 | 见下文「会话」。 |

**模型条**
- 列表接口：`GET /api/inference/models`。
- 内容：已注册 **训练 checkpoint**、**合并结果** 等。
- **`model_id`** 前缀约定：`lora:` / `merged:`。

**图像上下文（任选一种方式）**
- **`application/json`**：字段 **`import_task_id`**，或 **`image_workspace_path`**（工作区相对路径）；接口 **`POST /api/inference/chat`**。
- **`multipart`**：可上传 **`image` 文件**；后端写入 **`uploads/playground/`** 再推理。
- 产品与需求：**与「仅 LS 路径」长期目标并存**；说明中可区分 **「登记路径」** 与 **「沙盒上传」**。

**对话区**
- **多轮** `messages`。
- 与 **`infer_image`** 服务协作。

**会话**
- **`POST /api/inference/session`**
- **`GET .../sessions/{id}`**
- **`POST .../export`**（Markdown / JSON）

**空状态**：未选模型时引导先去训练或合并。

### 3.5 LoRA 合并

| 表单项 | 说明 |
|--------|------|
| 基础模型路径 | 与工作区相对路径或 Hub id 一致（见实现）。 |
| LoRA 路径 | 支持多个；可选从 **`GET /api/merge/training-candidates`** 等接口辅助选择。 |
| 输出路径 | 校验落在工作区内。 |
| 主操作 | `POST /api/merge/jobs`；状态与日志 `GET /api/merge/jobs/{id}`、`.../logs`；**取消** `.../cancel`；**校验** `.../validate`。 |
| 辅助 | 训练 run 日志/导出 zip：`GET /api/merge/training-jobs/{training_job_id}/train-run-logs`、`.../logs`、`.../export-zip`。 |
| 完成后 | 成功可跳转 **LoRA 验证** 试跑；失败展示日志与重试。 |

### 3.8 系统信息

| 展示项 | 注意 |

## 4. 全局模式与状态

- **任务长时间运行**：非阻塞。
- **任务长时间运行**：用户可离开页面，之后从任务列表或相关入口再进入。
- **训练日志**：详见 §3.3「训练日志区」。
- **训练日志**：等宽字体。
- **训练日志**：固定区域可滚动。
- **训练日志**：默认跟随日志尾部。
- **训练日志**：实现可用 **WebSocket** / **SSE** 或 **轮询**；滚底与「暂停跟随」行为须一致。
- **错误展示**：后端错误信息经中文化映射后再展示。
- **错误展示**：`Result` 不可用时至少展示 HTTP 状态。
- **错误展示**：若有 **trace id** 则一并展示。
- **仅中文**：菜单、按钮、表头、空状态、错误文案、Tooltip 均不以英文为主导语种。
